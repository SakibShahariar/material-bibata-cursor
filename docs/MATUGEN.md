# Matugen setup

Get a theme that matches your wallpaper with
[matugen](https://github.com/InioX/matugen) and the included post-hook.

The hook supports GNOME/GTK, KDE Plasma, Hyprland, Sway, and an opt-in Niri
configuration include. It preserves `XCURSOR_SIZE` when set and otherwise
tries to read the active Hyprland or GNOME cursor size before using 24 as a
fallback.

## Setup

1. Copy `scripts/cursor_matugen.sh`, `scripts/color_match.py`, and the
   repository-root `themes.json` into
   `~/.config/matugen/post-hook-scripts/`.
2. Add the template to `~/.config/matugen/config.toml`:

```toml
[templates.cursor]
input_path = "~/.config/matugen/templates/cursors.json"
output_path = "~/.config/colors.json"
post_hook = "~/.config/matugen/post-hook-scripts/cursor_matugen.sh"
```

3. Create `~/.config/matugen/templates/cursors.json` with:

```json
{
    "colors": {
        "color13": "{{colors.primary.default.hex}}"
    },
    "mode": "{{mode}}"
}
```

Before running the hook, build/install the cursor themes (for example,
with `just build`) so the matched preset is available locally.

The hook does **not** build or install themes: it picks the closest preset
in `themes.json` using `color_match.py` and applies that already-installed
theme. It uses Matugen's resolved `mode` to compare the dark presets (plus the
original Classic preset) for Dark mode or the `-Light` presets for Light mode. If a custom/older template omits
`mode`, it falls back to matching across all presets for compatibility.
Matching uses CIEDE2000; it does not recolor or rebuild a cursor to match
Matugen's exact primary hex value, so the result may be close rather than
identical.

When run directly from a repository checkout, it finds `themes.json` in the
repository root. When installed as a Matugen post-hook, keep `themes.json`
beside the copied script.

## Measuring palette coverage

The coverage analyzer tests **colors generated by Matugen**, not the input
seed colors directly. It requires Matugen 4.2.0 and runs:

```bash
python3 scripts/analyze_matugen_coverage.py \
  --matugen matugen \
  --json-output matugen-coverage.json
```

The deterministic input grid contains 216 source colors (24 hues, three
saturation levels, and three lightness levels). Each source is passed through
the nine non-Smart Matugen 4.2.0 scheme variants. The analyzer reads the
generated semantic `primary` role for both dark and light schemes, producing
3,888 generated primary-color samples.

Matugen's `scheme-smart` is deliberately excluded from this color-seed test.
The upstream implementation requires an image to detect its Smart variant and
mode; when given a hex color it warns and falls back to the default
Tonal Spot/dark behavior. Smart mode therefore needs image-based testing, not a misleading tenth
color-seed run.

Three measurements are reported separately:

- **Primary-only ΔE00:** distance from Matugen's generated primary color to
  the closest of the 56 Material cursor palettes. This measures the best
  available accent-color fidelity; the original Classic theme is excluded.
- **Current matcher score:** the existing 75% primary / 25% body score used by
  the hook. The live matcher considers all entries in `themes.json`,
  including Classic.
- **Selected-theme primary ΔE00:** distance from Matugen's generated primary
  color to the primary color of the theme the live weighted matcher actually
  selects. The report also counts cases where the weighted matcher selects a
  different theme from the primary-only winner and quantifies the resulting
  primary-fidelity regret. This distinguishes palette coverage limitations
  from choices made by the current weighting formula.

The color-seed report includes overall and per-scheme/mode distributions,
source-hue bands, generated-primary CIELAB hue/chroma regions, matcher
selection counts, and the worst primary-color matches.

### Matugen 4.2.0 controlled-grid baseline (before palette refinement)

The successful 216-seed run produced 3,888 generated primary samples across
the nine hex-compatible schemes and both modes. Against the 56 Material
palettes, primary-only ΔE00 was median **8.00**, p90 **15.25**, p95 **18.50**,
and worst **21.72**. The worst matches were dark, low-chroma red outputs in
Light mode (for example `#4c1d1d`, nearest `Pink-Pastel-Light`). Other weaker
regions included high-chroma yellow/green (CIELAB hue 60–120°, C* 55+) and
neutral low-chroma outputs (C* below 10).

The current live matcher score (75% primary / 25% body) was median **18.72**,
p90 **24.53**, p95 **34.83**, worst **34.83**. This score is not primary
fidelity: both components are compared with the same Matugen primary input.
The live weighted matcher selected a different theme from the primary-only
winner in **710/3,888 (18.3%)** samples. Its selected theme's primary-color
error was median **8.01**, p90 **15.34**, and worst **44.60**. The extreme case
was Monochrome Light (`#000000`), where body weighting selected `Noir`
instead of the nearest primary-only candidate `Cloud-Light` (ΔE00 18.50).

Restricting the same 75/25 score to the mode Matugen actually resolved
eliminated all **231 cross-mode selections**. Selected-primary ΔE00 improved
to median **8.01**, p90 **15.32**, p95 **18.50**, and worst **22.17**; samples
above ΔE00 15 fell slightly from 436 to 431. The matcher still differs from
the primary-only winner in 479/3,888 cases, so mode filtering addresses
cross-mode mistakes but does not eliminate body-weighting trade-offs.

These are reproducible controlled seed-color measurements, not a
representative sample of real wallpapers. The Smart fixtures described below
verify the Smart decision branches but likewise do not estimate real wallpaper
frequency. Do not recolor or merge palettes based on these grids alone.

### Pairwise palette separation and targeted refinements

The workflow measures pairwise distance between palette primary and body
colors across all **56 selectable palettes** (28 Dark and 28 Light): 1,540
total pairs, including 378 pairs within each mode. The pre-refinement report
found four same-mode primary pairs below ΔE00 3. They were refined without
merging or removing any of the 28 families:

| Palette | Previous primary | Updated primary | Close pair before |
|---|---|---|---|
| Charcoal | `#7591a3` | `#6790a4` | Charcoal / Slate — 2.93 |
| Midnight-Light | `#3a7714` | `#226d1e` | Midnight-Light / Sage-Light — 1.44 |
| Salmon-Light | `#ad1806` | `#a0131c` | Blush-Light / Salmon-Light — 2.50 |
| Sky-Blue-Light | `#0567b4` | `#1557bd` | Ice-Blue-Light / Sky-Blue-Light — 2.94 |

Only the four primary accent values changed; body and watch colors remain
unchanged. After the edits, **zero of the 1,540 primary-color pairs** are below
ΔE00 3. The four edited pairs now have clearly greater separation (about
6.2–9.2 ΔE00). The closest remaining pair is Brown-Light / Sand-Light at
3.12, followed by Deep-Blue-Light / Seafoam-Light at 3.20 and
Apricot-Light / Sunset-Light at 3.37. This is a targeted refinement, not a
claim that every palette pair is widely separated.

Body-color overlap remains at 41 pairs below ΔE00 3, including 38 of 378
Light pairs. This is largely because many Light presets use similarly pale
backgrounds, and it is not evidence that their cursor accent colors are
duplicates. For example, Mint-Light / Seafoam-Light body colors differ by
only ΔE00 0.21 while their primary colors differ by 15.53. The analyzer
therefore reports primary and body separation independently.

### Post-refinement Matugen 4.2.0 results

The successful 3,888-sample controlled grid confirms that the refinements did
not trade away Matugen coverage. Primary-only ΔE00 is now median **7.23**,
p90 **15.13**, p95 **18.50**, and worst **21.39** (mean **7.93**), compared
with the pre-refinement baseline of median **8.00**, p90 **15.25**, p95
**18.50**, and worst **21.72** (mean **8.18**). Samples above ΔE00 15 fell
from **419 to 403**.

The production mode-aware matcher now has selected-primary ΔE00 median
**7.27**, p90 **15.26**, p95 **18.50**, and worst **22.17**; it still has zero
cross-mode selections. It chooses a different theme from the primary-only
winner in **468/3,888 (12.0%)** samples, down from 479 (12.3%) before the
palette edits. The current 75/25 primary/body matcher score is median
**18.51**, p90 **24.52**, p95/worst **34.83**. As before, that weighted score
is not a primary-fidelity metric. The legacy no-mode fallback can still
select a cross-mode theme; normal Matugen templates pass the resolved mode.

The pinned 79-image exploratory wallpaper sample remains non-representative.
After the edits, nearest-primary ΔE00 is median **6.78**, p90 **11.72**, p95
**12.79**, and worst **18.50**. The mode-aware selected-primary p90 is
**11.77**, worst **18.50**, with no cross-mode selections; its mismatch from
the primary-only winner remains **3/79**. The unfiltered legacy matcher still
has a worst selected-primary error of **44.60** in this sample. The sample
does not establish general wallpaper coverage.

The gallery data at `docs/themes.json` is synchronized with the build source
`themes.json` and is checked by CI. The two static comparison matrix images
still need regeneration to complete the visual documentation update; they
must not be treated as previews of these new accent values until refreshed.
The successful Matugen 4.2.0 Smart regression run selected the expected
variant and mode for all eight fixtures. Across the selected-mode primary
colors, the median nearest-palette distance was ΔE00 8.91 and the worst was
18.50 (Monochrome Light, `#000000`, nearest `Cloud-Light`). The other fixtures
matched as follows: Neutral Dark 8.91, Neutral Light 13.38, Tonal Spot Dark
2.09, Tonal Spot Light 5.99, Vibrant Dark 0.00, and Vibrant Light 1.55.
These are nearest-primary measurements, not the live weighted matcher's
selection score. They should not be generalized to wallpaper populations.

A separate Smart-mode check generates eight deterministic solid-color PNG
fixtures. They cover Matugen's four Smart variants (Monochrome, Neutral,
Tonal Spot, and Vibrant) in both Dark and Light mode. The workflow verifies
that Matugen selects the expected variant and mode, then measures the selected
mode's primary against all 56 cursor palettes. It also reports the live 75/25
matcher selection and the selected theme's primary-color error separately.
These fixtures validate the
Smart decision paths; they are synthetic regression inputs, **not** a
representative wallpaper corpus. Real wallpaper-based coverage remains a
separate validation requirement.
The workflow also checks a pinned snapshot of the CC0-1.0
[Rosé Pine Wallpapers](https://github.com/rose-pine/wallpapers) repository.
It analyzes supported JPG, PNG, and WebP images from its Generative,
Illustration, Photography, Minecraft, Miscellaneous, and OS folders (79 images
in the pinned snapshot). Anime and Manga folders are intentionally excluded.
This is a small, curated real-image sample—not a random or representative
wallpaper population—and its palette is community-curated. The report keeps
this exploratory corpus separate from the synthetic Smart fixtures and
controlled seed grid. All reports are uploaded as a workflow artifact.

The pinned 79-image run selected Matugen Smart variants as follows:
Neutral **45**, Tonal Spot **29**, Monochrome **4**, and Vibrant **1**; 62
outputs were Dark and 17 Light. Nearest-primary ΔE00 was median **6.78**,
p90 **11.72**, p95 **12.79**, and worst **18.50**. The live weighted matcher
selected a different theme from the primary-only winner in **5/79** cases;
its selected-primary median was **6.78**, p90 **11.87**, and worst **44.60**.
Mode-aware matching reduced the mismatch count to **3/79**, with selected-primary p90 **11.77** and worst **18.50**, and no cross-mode selections.

The source snapshot is pinned to
ee39a37b24ab7700cc4d52f50b01a5d13df6a865. Even with the broader category mix,
these wallpapers remain a small, curated Rosé Pine collection, not a random
population, and the sample does not establish general wallpaper coverage.
This sampling is a reproducible coverage study of Matugen's color-generation
pipeline; it is not a claim that every possible wallpaper or source color has
been sampled.

## Niri support

The Matugen post-hook can also update the cursor theme used by
[Niri](https://github.com/niri-wm/niri).

Add this line to your Niri configuration, normally
`~/.config/niri/config.kdl`:

```kdl
include "cursor-theme.kdl"
```

If your `config.kdl` already has a `cursor` block with an `xcursor-theme`
setting, remove that setting to avoid configuring the theme in two places.
If the block contains no other settings afterward, remove the entire block.

The generated `cursor-theme.kdl` file must be in the same directory as the
main Niri configuration. It looks like:

```kdl
cursor {
  xcursor-theme "Bibata-Material-Teal"
}
```

The theme name changes automatically according to the color selected by the
Matugen hook.

### Requirements

- Install the matching `Bibata-Material-*` cursor themes before running the hook.
- Keep the `include "cursor-theme.kdl"` line in your main Niri configuration.
- Niri support has not yet been verified on a live Niri session.
